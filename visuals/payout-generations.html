Case study · Stripe reconciliation

Three versions of one weekly reconciliation

From 4 hours a week by hand, 6 at month end, to under 30 minutes in KNIME, to a console that checks every week 16 ways and keeps every run.

Generation 1

By hand

4 hrs
a week, 6 at month end
  • Limit: Stripe downloads too big for Excel, pushed through Tableau first
  • Limit: Consolidated with Power Query, then every tab checked by hand
  • Entries shaped into NetSuite import files by hand, and the net payout reviewed by the CFO

The process being replaced

Generation 2

KNIME rebuild

< 30 min
door to door, review included
  • Added: Execution itself runs 5 to 15 minutes
  • Added: A completeness branch catches any fee outside the nine known categories
  • Added: Builds the NetSuite journal-entry import, keyed on External ID so a re-import cannot double-post
  • Added: Run side by side with the manual process before cutover
  • Limit: Ten parameters typed by hand at the start of every run
  • Limit: Every file path typed into the workflow, and each person sets up their own credentials
  • Limit: A re-run overwrites what was booked, and no snapshot is kept
  • Limit: Its query window was too narrow and missed backdated Stripe entries

Built, tested and put into production alone

Generation 3

Python console

16 checks
before anything is exported
  • Added: Every run saves the data it used, with a fingerprint, so any week can be replayed
  • Added: Nothing accrued twice, checked by Stripe's own row ID
  • Added: 14 of 16 client groups rebuild from the snapshot to the cent, and the other two are explained
  • Added: Caught a booked week where hand-typed dates added a day that was already booked
  • Limit: Still in testing next to the manual process, not posting yet
