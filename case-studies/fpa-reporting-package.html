Case study

The thirty-minute re-run

The work described here is at TixTrack, where I'm a senior financial analyst.

Every time we closed a period I'd pull the reports, analyze the numbers and write the commentary, and every time something would have to change.

Any change meant I had to pull all the reports again and consolidate them again, which took me 30 minutes each time.

It happened maybe 2 to 4 times per close, I never actually counted.

So you can imagine what it's like when you thought you were already done and there's pressure to finish and send the package so the CEO can review it.

Building it

I built the dashboard in July 2026, once my ERP and close platform were connected to an AI assistant and the gears started grinding.

The first time I tried pulling ERP data through Claude, it burned through my usage allowance really fast because it kept retrying queries it didn't have access to.

Numeric already had the same data, more organized and cheaper to pull, so I built on that instead and NetSuite was just the check.

As I got better with Claude Code, I built the two NetSuite reports it needed myself so it could pull cheaply and accurately. I tested it, and on September 11 we switched the P&L and balance sheet back to NetSuite and reloaded all 8 months that day.

Claude pulls the reports, the code builds every number, and at the end everything gets tied back to the ERP account by account and in total.

Numeric still has the commentary, the balance sheet by entity and the department detail.

The dashboard has 8 views: overview, P&L detail, income statement, balance sheet, balance sheet by entity for our 6 legal entities, adjusted EBITDA, budget vs actuals, and a page for data and runs.

Budget vs actuals switches between the original budget and the reforecast, 12 months each, and adjusted EBITDA is net ordinary income plus depreciation, amortization and stock comp.

I can export the whole package in one click, plus a second version in the format the CEO expects.

I didn't write the code myself, Claude wrote it. My part is telling it what the dashboard has to produce and checking the output against the source data.

Catching drift

I wanted to make sure we'd catch any drift between what we already sent for past periods and any adjustments we make after.

So every time I load a month it gets saved as a run instead of overwriting the last one, and if a closed month comes back different on a reload, it gets flagged.

From July 22 to September 11 there were 74 runs. 49 passed, 16 were provisional and 9 were for months that were still open, and no closed month changed on any of them.

But that also means the drift check hasn't caught anything yet, so I don't know for sure it works on a real change.

Every closed month so far this year, January to August, ties two ways. Assets equal liabilities plus equity within $0.02, and net income ties to the financial package.

What changed

A full run takes me under 5 minutes now, and I timed that too.

So now when something changes after close, I just run it again.

What didn't work

I tried having Claude analyze the numbers, find the variances and write the commentary, but it was bad so I reverted it back.

The commentary is written in Numeric's flux reports and pulled into the dashboard and the exports, and the numbers come from SQL and Python.

What it still can't do

The executive summary is empty for every month, and the build only carries one summary tagged to one month, so even if I wrote them all it wouldn't fix it.

The commentary cells can still be edited on the dashboard, and an edit there stays in that browser and never goes back to Numeric. Nobody edits there, but nothing stops them either, so I need to make those cells read-only.

The prepaid and accrual schedules are still maintained by hand.

The overview still says "Numeric consolidated basis" even though the numbers come from NetSuite now.

And the balance sheet is off by up to $0.02 in some months and the check lets it pass. I hate that, it should tie to the penny.

What's next

I'm rebuilding the prepaid and accrual schedules directly from ERP data so the whole method is deterministic end to end, and that's in progress.

I'm also being brought into the FP&A reforecast cycle, wiring the VP of Finance's live reforecast into the leadership reporting dashboard so it refreshes continuously and locks each quarter. That's in progress too.
